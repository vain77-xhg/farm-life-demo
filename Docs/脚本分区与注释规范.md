# 脚本分区与注释规范

当前项目统一采用：**功能一句话、变量说明用途、复杂方法分步骤。**

## 固定保留八个分区

所有项目脚本按下面顺序排列，暂时没有内容的分区也保留，方便以后添加代码。

```csharp
// ==================== 字段 ====================

// ==================== Unity 生命周期 ====================

// ==================== 初始化 ====================

// ==================== 对外接口 ====================

// ==================== 核心逻辑 ====================

// ==================== 事件响应 ====================

// ==================== 内部辅助 ====================

// ==================== 调试显示 ====================
```

| 分区 | 放什么 |
| --- | --- |
| 字段 | 配置数值、对象引用、运行状态、常量 |
| Unity 生命周期 | 当前实际需要的 Awake、Start、Update、OnDestroy 等回调 |
| 初始化 | 保存外部依赖、创建和准备对象的方法 |
| 对外接口 | 其他脚本调用的功能入口，或编辑器菜单入口 |
| 核心逻辑 | 移动、查找交互目标、异步加载等具体功能 |
| 事件响应 | 接收事件或按钮点击的回调 |
| 内部辅助 | 被其他方法复用的辅助操作 |
| 调试显示 | Gizmos 等辅助绘制方法 |

一个方法只放在一个分区。既供外部调用又作为事件回调的方法，可以放在“对外接口”，例如 `UIManager.ToggleInventory()`。

同一组界面的打开、关闭、切换方法可以在“对外接口”中按功能集中排列，用普通小标题区分背包、设置等。直接配套的私有关闭回调也可以随组放置，例如 `CloseSettings()`；它的访问权限仍由 `private` 决定，事件身份仍由订阅决定。八个固定分区继续保留。

普通类、常量类和编辑器工具也保留空分区。它们不必因此继承 `MonoBehaviour`，也不用补写空的生命周期方法。

这些分隔线是普通注释，不影响执行。保留分区不等于必须创建对应方法，不使用 `#region`。

## 方法：一句话说明功能

类和方法使用中文 `<summary>`，说明当前完成的功能。不要在里面写长段解释或未来计划。

- 有参数：用 `<param>` 分别说明参数的用途。
- 有返回值：用 `<returns>` 说明返回结果；`void` 方法不用写。
- 有泛型类型参数：用 `<typeparam>` 说明类型参数用途。

方法名称放在哪里不决定它什么时候执行。`Initialize()` 需要调用者主动执行；Unity 回调的名称和大小写要准确。

## 变量：说明保存什么、起什么作用

每个字段、局部变量和 `foreach` 迭代变量都单独说明。参数使用 `<param>` 说明。注释紧挨对应声明，保持简短。

```csharp
// _moveSpeed：走路速度，单位为世界单位/秒。
[SerializeField] private float _moveSpeed = 3f;

// closestDistance：当前最小距离，初始设为最大值。
float closestDistance = float.MaxValue;

// collider：本次从数组中取出的碰撞体。
foreach (Collider2D collider in colliders)
{
    // 在这里处理当前碰撞体。
}
```

类型已经写在声明中；注释重点解释这个变量在当前功能中扮演什么角色。必要时补充初始值的含义或数值单位。

`[SerializeField]` 让 Unity 保存私有字段，并在 Inspector 中显示。它不会自动查找引用。预制体中已保存的参数供创建实例时使用，脚本中的初始化值作为新组件的默认值。

## 逻辑：按执行顺序写关键步骤

复杂方法使用“第一步、第二步……”说明主要流程。判断或循环内部只补充关键条件，不逐行翻译语法。简单的单步方法可以只写功能说明。

```csharp
/// <summary>
/// 计算两个整数的和。
/// </summary>
/// <param name="a">第一个加数。</param>
/// <param name="b">第二个加数。</param>
/// <returns>两个加数的和。</returns>
private int Add(int a, int b)
{
    // 第一步：计算并保存结果。
    // sum：保存加法结果的整数。
    int sum = a + b;

    // 第二步：返回结果。
    return sum;
}
```

当前 `PlayerController.TryInteract()` 使用四步：检测附近碰撞体、准备最近目标记录、逐个比较并记录、执行交互。注释随逻辑一起更新。

## 使用模板

模板文件：[MonoBehaviourTemplate.cs.txt](Templates/MonoBehaviourTemplate.cs.txt)。放在 `Docs` 下供复制，不参与游戏脚本编译。

1. 创建新脚本，把模板类名改为实际类名，并与文件名保持一致。
2. 保留八个分区，只实现当前需要的字段和方法。
3. 方法写功能说明，变量写用途，复杂流程写步骤。
4. 事件订阅和清理放在实际使用的位置，注释说明对应操作。
5. 检查代码调用、引用和运行结果，再进行 Git 提交。

当前项目继续保留 `InPutManager` 的拼写。注释与排版整理时，保留现有字段名、方法名、访问权限和运行逻辑。
