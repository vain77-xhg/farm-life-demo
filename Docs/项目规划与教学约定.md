## 四、当前真实项目基线

截至本次更新，Assets 下有 17 个项目 C# 脚本，包含编辑器工具。主要能力如下：

- `Bootstrap` 是现有启动入口，处理单例与 `DontDestroyOnLoad`，运行时创建资源、UI、输入、事件、场景、文本和游戏状态管理器，再传入依赖。文本初始化及 UI/玩家所需引用的准备先于实际使用；`GetTextManager()`、`GetGameStateManager()`、`GetEventManager()` 返回已有组件引用，不重复创建管理器。
- `ResourceManager` 提供 Resources 预制体加载、实例化和 `LoadTextAsset(string path)` 文本资源加载。文本加载成功时返回 `TextAsset`，失败时输出日志并返回 null。
- `TextManager` 保存资源管理器引用，读取 `Data/文本表`，拆分单行 CSV 记录并建立 `Dictionary<int, string>`。`GetText(int textId)` 查询文字，编号缺失时报错并返回空字符串。
- `EventManager` 支持无参数、int 参数和 string 参数事件。
- `InPutManager` 发布界面事件，并提供移动、奔跑和 E 键交互输入查询。
- `SceneLoader` 使用协程等待异步加载，有重复请求拦截、场景可加载检查、进度和完成日志。
- `UIManager.Initialize()` 保存资源、事件和状态管理器。背包与设置预制体继续按需创建并复用；只有设置面板开关接入操作权限：显示成功后调用 `SetPlayerControl(false)`，隐藏后调用 `SetPlayerControl(true)`。失败提前返回时不改变权限，重复打开也会更新权限。
- `SettingsUI` 的关闭按钮发布关闭请求，UIManager 的 `CloseSettings()` 接收并处理；ESC 通过切换设置事件进入同一组开关方法。背包目前只有界面开关，没有物品数量/格子数据，也未接入操作权限限制。
- `GameStateManager` 保存默认 true 的 `_canPlayerControl`；`CanPlayerControl()` 查询，`SetPlayerControl(bool canControl)` 修改。它不直接移动玩家、不控制界面、不修改世界时间，也没有新增空初始化方法或独立单例。
- `FarmSceneController` 创建玩家，通过 `PlayerController.Initialize(InPutManager, GameStateManager)` 传入已有输入和状态管理器，再设置相机跟随目标。
- `PlayerController` 在 Update 查询操作权限：禁止时将 `_moveDirection` 清零并返回，跳过移动输入与 E 键交互；允许时读取方向和交互键。FixedUpdate 调用 Move，Move 再查询权限，禁止时将 `Rigidbody2D.velocity` 清零并返回，允许时继续走路/左 Shift 奔跑。
- `CameraFollow` 在 LateUpdate 跟随玩家 X、Y 坐标并保留相机 Z 坐标。
- 交互使用 `Physics2D.OverlapCircleAll` 获取附近碰撞体，通过 `GetComponent<InteractableObject>()` 筛选，再按位置距离选择最近的可交互组件。
- `InteractableObject` 保存 `_textId`；`Interact()` 获取文本管理器并查询，空文字时结束，有文字时在方法内部取得已有事件管理器，发布 `ShowInteractionText` 的 string 事件。已移除该处直接打印文字的旧逻辑，不在字段初始化时访问 Bootstrap。
- `UIManager` 订阅交互文字显示事件，`ShowInteractionText(string)` 首次加载 `UI/InteractionUI` 并获取/缓存组件，随后复用同一实例，每次更新文字并显示；创建失败时结束，缺少组件时销毁失败实例并报错。销毁 UIManager 时取消对应订阅。
- `InteractionUI` 是新增的预制体控制脚本，用序列化字段绑定 ContentText 的 TMP_Text 组件，`SetText(string)` 更新组件的 text 属性。脚本和预制体均由用户制作，保留八个分区。
- 交互提示按用户选择显示约 3 秒后自动隐藏；每次显示停止旧协程，再启动并保存新 Coroutine。`HideInteractionTextAfterDelay()` 使用 WaitForSecondsRealtime，结束时隐藏对象并清空协程引用。协程由 UIManager 启动，隐藏 InteractionUI 保留实例，之后可复用。
- 农场已有 `TestObstacle` 与 `FarmSing` 两个测试目标，场景分别保存文本 ID 300001、300002；名称以工程实际拼写为准。
- 交互范围使用红色 Gizmos 显示。玩家预制体已保存 `_interactRadius = 0.8`，用户确认手感舒服；脚本中的 `1.5f` 是默认值，不要因此重置预制体配置。
- `GameEvents` 与 `GameScenes` 继续用于事件名称和场景名称。
- 编辑器菜单“工具/打开启动场景”用于打开 `SampleScene`。

启动时要从 `SampleScene` 进入。直接运行没有 Bootstrap 的 `FarmScene`，不能据此认定输入或事件系统断裂。

`Bootstrap.StartGame()` 目前仍保留自动打开背包、创建并隐藏 TestCube 的启动测试。它们属于后续可整理内容，尚未清理。

最近目标选择代码已经实现并做过代码检查。用户明确暂缓了那次多目标运行测试，不要将它写成已通过，也不要把它当成进入文本表教学的前置任务。

已接通文本配置、设置面板操作权限和交互提示 UI 基础。尚未实现：自动导表工具、世界暂停与多来源权限规则、时间系统、物品数据系统、背包存储和存档系统；第一阶段仍在继续。

当前设置面板与操作权限的数据流：

```text
ESC 或设置关闭按钮
    → EventManager 转发界面请求
    → UIManager 实际打开/关闭设置面板
    → GameStateManager 保存操作权限 false/true
    → PlayerController 查询同一个管理器
    → Update 决定是否读取移动输入、执行场景交互
    → Move 决定是否设置移动速度，禁止时将刚体速度设为零
```

操作权限基础的边界与验证：

- UIManager 与 PlayerController 保存的是同一个管理器组件的引用；传递引用不创建第二个管理器，也不把 bool 快照复制到玩家。
- 事件用于转发开关请求；权限查询与修改使用直接方法调用。限制玩家操作期间，输入管理器继续处理 ESC，SettingsUI 的关闭按钮监听也继续工作。
- 当前只连接设置面板，背包开关不改变权限。世界时间和物理世界暂停尚未实现，多界面/其他来源同时限制操作的合并规则后续设计。
- 用户反馈启动时临时禁止/恢复测试通过；临时 `_gameStateManager.SetPlayerControl(false)` 启动测试代码已删除。
- 用户反馈移动时打开设置能够停止移动、禁止 E 交互，ESC 和关闭按钮关闭后均能恢复，重复开关验证通过。该结果来自用户编辑器运行反馈，助手没有独立运行编辑器或编译工程。

编号与引用约定：

- 上表全部是文本 ID，不代表物品、NPC、任务本身的配置 ID；其他数据类别的数字编号规则另行规划。
- 所有文本 ID 唯一；没有列出的号段与九位 ID 暂时保留，不预先生成空数据。
- 同一句通用文字可以共用 ID；修改文字保留 ID，旧 ID 不分配给无关新文字。
- 位数和号段用于管理与校验，不要求建立不同的文本管理器。文本仍可放在一张表中查询。
- 字段明确写用途，例如 `_textId`、`itemId`、`NameTextId`、`DescriptionTextId`。
- 物品表通过名称文本 ID、说明文本 ID 引用文本表，不能将物品身份与显示文字混在一起。
- 定义 ID 表示“哪一种数据”。需要独立存档的场景实体，以后再设计实例 ID；当前路牌不额外引入实例 ID。

## 六、当前文本数据流与职责

```text
Excel / WPS 编辑 ID、Text
    → 用户导出 UTF-8 CSV
    → Unity 导入为 TextAsset
    → Bootstrap 初始化 TextManager
    → ResourceManager.LoadTextAsset("Data/文本表") 返回资源
    → TextManager.LoadTexts() 解析并保存 Dictionary<int, string>
    → InteractableObject.Interact() 使用自己的 _textId 查询
    → TextManager.GetText() 返回文字
    → InteractableObject 发布 ShowInteractionText 事件，携带文字
    → EventManager 调用 UIManager 已登记的接收方法
    → UIManager 创建或复用界面，InteractionUI.SetText() 更新文字
    → 显示并重新计时，约 3 秒后隐藏，保留实例供复用
```

实际 CSV：`Assets/Resources/Data/文本表.csv`；Resources 路径：`Data/文本表`，不含扩展名。中文文件名是当前实际选择，不需要改成旧计划中的 `Texts.csv`。

| 部分 | 当前职责 |
| --- | --- |
| Bootstrap | 创建并提供已有管理器引用，文本初始化后才启动游戏流程 |
| ResourceManager | 加载 TextAsset，不负责拆分文本数据 |
| TextManager | 解析文本表，保存字典，按 ID 返回文字 |
| InteractableObject | 保存文本 ID，交互时查询文字并发布显示请求 |
| EventManager | 按事件名称转发已查询的 string 文字 |
| UIManager | 订阅显示请求，加载/复用界面，更新文字并管理隐藏计时 |
| InteractionUI | 保存 TMP_Text 引用，通过 SetText 更新实际显示内容 |

当前读取与查询约定：

- `LoadTexts()` 跳过首行表头，按换行拆分记录、去掉行尾回车并跳过空白行；表头目前按约定填写，不做名称校验。
- `ParseCsvline()` 保留用户现有拼写，处理引号内英文逗号、连续双引号表示一个文字双引号，以及引号未闭合时返回空数组。当前是支持约定格式的单行解析器，不是完整 CSV 格式校验器。
- 用户明确暂不支持单元格内实际换行，每条记录占一个物理行。以后有需要再讨论；UI 自动换行不属于这里的多行 CSV 支持。
- `LoadTexts()` 检查两列格式、整数编号和表内重复编号；错误行输出日志并跳过，其他正常行继续加入字典。
- 资源加载成功后先 `_texts.Clear()` 再填充，避免重复加载时将旧记录当作新表重复编号；资源加载失败时保留原有字典。当前是清空后逐行导入，未实现整表校验通过后统一替换。
- `GetText()` 使用 `TryGetValue`；编号不存在时输出错误并返回空字符串。`Interact()` 收到 null 或空字符串时直接结束，不再打印空日志。
- 启动时加载，交互时查询已有字典；没有新增每次交互重读文件或自动监听 Excel 的逻辑。
- 逐条打印编号与文字的测试日志已移除，保留加载数量和错误日志。面向玩家的文本集中管理，开发日志继续由代码输出。

当前交互提示资源与验证：

- 预制体位于 `Assets/Resources/UI/InteractionUI.prefab`，根对象挂 Canvas、CanvasScaler、GraphicRaycaster 和 InteractionUI；层级为 `InteractionUI → Panel → ContentText`，序列化字段绑定到该实例内部的文字组件。
- 根画布使用 Screen Space - Overlay，参考分辨率 1920×1080，Match 为 0.5。背景底部居中、900×180、上移 60；文字四向拉伸并留 20 边距，字号 32、黑色、水平与垂直居中。居中和当前背景颜色是用户的显示选择。
- 使用已有 SourceHanSansSC-Regular SDF 字体。当前字体 diff 增加了“交互提示预览”和默认预览文字的字形、字符及图集数据；已检查并建议保留，与本轮新增 UI 一起提交，不修改字体源文件或 `.meta`。

- 提示是非模态显示，不调用 SetPlayerControl；设置面板仍负责自己的操作限制。没有增加关闭按钮、离开范围自动关闭、NPC 分支对话或日历功能。
- 本轮助手核对保存代码、预制体引用、事件配对、协程和 Git 差异；用户反馈的编辑器验证与助手代码检查分别记录，助手没有独立编译或运行 Unity。

## 七、教学方式与沟通要求

- 使用中文，语气友好、清楚，可以称呼用户“宝宝”。
- 一次讲一个小知识点，安排一个可完成的小任务。
- 先解释“是什么、为什么做、完成后解决什么”，再给任务。
- 框架或数据功能先讲清数据从哪里来、交给谁处理、最后到哪里。
- 重点检查逻辑、结构、对象引用、初始化顺序和生命周期。
- 不把一般手打拼写、大小写或排版差异当成教学重点；影响编译、Unity 回调或引用的错误仍需清楚指出。
- 尊重用户自己选择的颜色和细节；`InPutManager` 的类名与文件名拼写明确保留。
- 用户没看懂时先停下来解释，不连续推进新概念。

每轮代码教学按以下方式：

1. 读取实际项目代码，确认当前进度。
2. 解释当前小任务的用途和执行流程。
3. 对尚未掌握的关键字或 API 给出解释和必要片段。
4. 让用户亲自编写代码或操作 Unity。
5. 用户完成后重新读取实际文件，检查实现。
6. 附上本次改动范围的完整参考方法或脚本，供对照。
7. 明确实际验证结果与尚未验证的部分，再决定下一步。

避免重复贴不相关的大段代码。参考代码围绕本轮修改；修改一个方法时，通常给这个方法的完整版本即可。

## 八、代码操作权限与工程模式

- 新功能默认由用户亲自编写。“继续”“下一步”“帮我看看”不等于授权直接代写玩法代码。
- 用户明确要求直接修改时，按本轮授权执行，例如已授权的注释、分区、排版和文档整理。
- 检查、讲解与规划可以直接进行，无需每一步重复确认。
- 不自动创建整套场景、玩家、UI 或玩法实现，替代用户的学习过程。
- 以实际工程文件、场景、预制体和设置为准，历史聊天和截图用于补充背景。
- 现行模式：在编辑器中制作预制体外观、布局和必要引用，代码负责加载、实例化、初始化、行为与显示控制。
- Bootstrap 通过代码创建管理器的现有方式继续保留；不恢复为纯代码搭建所有 UI 的旧模式。
- 游戏内跨系统通知适合使用事件；移动状态和交互按键继续通过输入管理器查询，不要求所有调用都改成事件。

## 九、注释与固定分区要求

完整规范见 [脚本分区与注释规范.md](脚本分区与注释规范.md)，模板见 [MonoBehaviourTemplate.cs.txt](Templates/MonoBehaviourTemplate.cs.txt)。

- 类和方法用简短中文 `<summary>` 说明功能。
- 参数用 `<param>` 说明作用；有返回值时写 `<returns>`；泛型类型参数使用 `<typeparam>`。
- 每个字段、局部变量和 foreach 迭代变量分别说明“保存什么、起什么作用”。
- 复杂方法按“第一步、第二步……”标注关键执行流程；简单单步方法不硬凑步骤。
- 注释简短、关键，随当前代码更新，不写长篇背景和未来计划。
- 使用普通注释分隔，不使用 `#region`。

所有脚本固定保留以下八个分区，未使用的分区也保留：

```csharp
// ==================== 字段 ====================
// ==================== Unity 生命周期 ====================
// ==================== 初始化 ====================
// ==================== 对外接口 ====================
// ==================== 核心逻辑 ====================
// ==================== 事件响应 ====================
// ==================== 内部辅助 ====================
// ==================== 调试显示 ====================
```

保留分区不等于添加空方法。常量类、普通类和编辑器工具保留空标签即可，不因此改变继承关系。

## 十、Git 协作方式

- Git 由用户操作。默认不代为暂存、提交、推送或回滚；如用户以后明确改变授权，再按最新要求执行。
- 用户给出待提交列表或截图时，按显示顺序说明勾选哪些，并提供可复制的提交说明。
- 用户只要提交内容时，给出覆盖当前实际改动的说明，不把玩法修改误写成仅注释整理。
- 结合实际 diff 判断哪些保留、哪些还原，不按文件扩展名一概处理。
- 新增 Unity 脚本、预制体等资源与其 `.meta` 配套提交。
- 保留用户已有的未提交修改。注释和排版任务核对整理前后的代码内容，避免改变逻辑或序列化字段。

## 十一、后续协作的技术提醒

- 团结引擎的 `.scene` 和 `.meta` 表示可能与常见 Unity 文本格式不同。现有 `.meta` 使用特殊 GUID 表示，不能只按长度或与场景 GUID 字面不同就判定损坏，也不要擅自重写。
- IDE 提示 `OverlapCircleNonAlloc` 属于性能建议；当前按 E 执行一次查询的代码可用于学习，不作为必须立即重构的问题。
- 明确区分代码检查、独立编译检查和实际编辑器运行验证，不把一种检查写成另一种已完成。
- 后续若用户更改阶段、优先级或教学方式，更新本文及相关查阅入口，避免沿用已被替代的旧安排。
