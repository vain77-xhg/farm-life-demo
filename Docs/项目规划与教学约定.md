## 四、当前真实项目基线

截至 2026-11-16，Assets 下有 20 个项目 C# 脚本，包含编辑器工具。各脚本职责与完整调用链见 [脚本职责与执行流程](脚本职责与执行流程.md)。

- `Bootstrap` 保留单例与 DontDestroyOnLoad，创建资源、UI、输入、事件、场景、文本、游戏状态和时间管理器并传入依赖。所有管理器先创建，再完成订阅和文本加载，最后执行 StartGame。获取管理器的方法返回已有引用，不重复创建。
- `ResourceManager` 负责 Resources 预制体/TextAsset 加载和预制体实例化；`TextManager` 负责解析 `Data/文本表`，建立 int ID→string 文字字典并查询。两者不替 UI 决定显示状态。
- `EventManager` 分别保存无参、int、string 回调，发布时立即调用已订阅回调。`InPutManager` 发布 Tab/ESC 界面请求，并提供移动、奔跑、E 键查询，输入本身不直接移动玩家。
- `SceneLoader` 订阅 string 场景请求，检查场景可加载性和重复请求，用协程等待异步加载完成；保留 progress/isDone 日志与取消订阅。
- TimeManager 已接启动：Bootstrap 保存 `_timeManager`，CreateManagers 将其作为第 8 个管理器创建。它没有外部依赖，不添加空 Initialize。初始分钟为 6*60，GetHour()/GetMinute() 返回真实小时/分钟；Update 检查非正阈值后累计 Time.unscaledDeltaTime，用 while 每消耗足额秒数推进 1 游戏分钟，默认 0.7 现实秒/游戏分钟。每次推进后的 Debug.Log 是临时 Console 验证，输出真实分钟，不是时钟 UI。
- 用户已反馈“正常输出，没有红色错误”，记录为时间基础的用户 Console 运行验证通过；助手仅静态审阅，未独立编译或运行。
- `UIBase` 已实现 Show/Hide、序列化 `_canPlayerControl` 及 CanPlayerControl()。`InventoryUI`、`SettingsUI`、`InteractionUI` 均继承它，UIManager 缓存对应组件并用 UIBase `_currentUI` 记录当前界面。
- `UIManager.CreateUI<T>()` 在创建边界加载实例、GetComponent 检查、设置父对象并隐藏待用；失败返回 null、缺组件销毁失败实例。OpenInventory/OpenSettings 准备成功后才通过 ShowUI(UIBase) 替换当前界面，按目标规则更新玩家权限。
- `SettingsUI` 自己初始化关闭按钮监听并配套取消；OpenSettings 首次创建成功后正确调用 `_settingsUI.Initialize(_eventManager)`。`InventoryUI` 暂无依赖，未添加空初始化。
- `CloseUI(UIBase)` 校验目标非空且确为当前界面，然后隐藏并恢复玩家权限。CloseSettings 保持 private 并调用 CloseUI(_settingsUI)；设置开关已包含在用户反馈无问题的 UI 检查中。
- `InteractionUI` 已继承 UIBase，通过 TMP_Text 和 SetText 更新文字；预制体 `_canPlayerControl: 1` 允许操作玩家。ShowInteractionText 用 CreateUI<InteractionUI> 创建，正确检查 `_interactionUI` 后 SetText、ShowUI 并重启计时，参加 `_currentUI` 统一互斥。
- 提示约 3 现实秒自动关闭；重复显示重置计时，隐藏后复用。CloseCurrentUI 停止并清空旧计时；等待结束先清协程句柄再 CloseUI(_interactionUI)，关闭目标检查避免旧请求误关新界面。
- `GameStateManager` 保存玩家操作权限。UIManager 与 `PlayerController` 使用同一引用；玩家在 Update 禁止时清空方向并跳过输入/E 交互，在 Move 禁止时清零刚体速度。界面快捷键继续处理。该权限不是游戏时钟或整个物理世界暂停。
- `FarmSceneController` 创建玩家，传入已有输入/状态管理器，再设置相机目标；`CameraFollow` 在 LateUpdate 跟随 X/Y 并保留 Z。
- `PlayerController` 检测附近碰撞体，筛选 `InteractableObject` 并选最近目标。交互组件保存文本 ID，调用时查询文字、空文字结束，否则取得已有事件管理器并发布 ShowInteractionText string 事件。
- `GameEvents`、`GameScenes` 统一事件与场景名称；`StartupSceneTools` 提供“工具/打开启动场景”菜单。

从 SampleScene 启动；直接运行没有 Bootstrap 的 FarmScene，不能据此判断输入/事件断裂。StartGame 仍保留自动打开背包、创建并隐藏 TestCube、发布农场加载请求，不擅自清理。

玩家预制体已保存交互半径 0.8，保留用户手感设置，不因脚本默认 1.5 重置。农场测试交互目标仍使用文本 ID 300001、300002。

| 6 位 | 200000～299999 | 操作结果与系统提示 | 背包已满、金币不足、保存成功 |

| 7 位 | 2000000～2999999 | 种植、制作与生产说明 | 作物生长条件、配方说明、加工说明 |

编号与引用约定：

- 上表全部是文本 ID，不代表物品、NPC、任务本身的配置 ID；其他数据类别的数字编号规则另行规划。
- 所有文本 ID 唯一；没有列出的号段与九位 ID 暂时保留，不预先生成空数据。
- 同一句通用文字可以共用 ID；修改文字保留 ID，旧 ID 不分配给无关新文字。
- 位数和号段用于管理与校验，不要求建立不同的文本管理器。文本仍可放在一张表中查询。
- 字段明确写用途，例如 `_textId`、`itemId`、`NameTextId`、`DescriptionTextId`。
- 物品表通过名称文本 ID、说明文本 ID 引用文本表，不能将物品身份与显示文字混在一起。
- 定义 ID 表示“哪一种数据”。需要独立存档的场景实体，以后再设计实例 ID；当前路牌不额外引入实例 ID。

## 六、当前文本数据流与职责

```text
Excel / WPS 编辑 ID、Text
    → 用户导出 UTF-8 CSV
    → Unity 导入为 TextAsset
    → Bootstrap 初始化 TextManager
    → ResourceManager.LoadTextAsset("Data/文本表") 返回资源
    → TextManager.LoadTexts() 解析并保存 Dictionary<int, string>
    → InteractableObject.Interact() 使用自己的 _textId 查询
    → TextManager.GetText() 返回文字
    → InteractableObject 发布 ShowInteractionText 事件，携带文字
    → EventManager 调用 UIManager 已登记的接收方法
    → UIManager 通过 CreateUI 创建或复用界面，InteractionUI.SetText 更新文字，ShowUI 统一切换
    → 重启约 3 现实秒计时，结束先清句柄再 CloseUI，保留实例复用
```

实际 CSV：`Assets/Resources/Data/文本表.csv`；Resources 路径：`Data/文本表`，不含扩展名。中文文件名是当前实际选择，不需要改成旧计划中的 `Texts.csv`。

| 部分 | 当前职责 |
| --- | --- |
| Bootstrap | 创建并提供已有管理器引用，文本初始化后才启动游戏流程 |
| ResourceManager | 加载 TextAsset，不负责拆分文本数据 |
| TextManager | 解析文本表，保存字典，按 ID 返回文字 |
| InteractableObject | 保存文本 ID，交互时查询文字并发布显示请求 |
| EventManager | 按事件名称转发已查询的 string 文字 |
| UIManager | 订阅请求，创建/复用并统一切换界面，更新权限及提示关闭计时 |
| InteractionUI | 保存 TMP_Text 引用，通过 SetText 更新实际显示内容 |

当前读取与查询约定：

- `LoadTexts()` 跳过首行表头，按换行拆分记录、去掉行尾回车并跳过空白行；表头目前按约定填写，不做名称校验。
- `ParseCsvline()` 保留用户现有拼写，处理引号内英文逗号、连续双引号表示一个文字双引号，以及引号未闭合时返回空数组。当前是支持约定格式的单行解析器，不是完整 CSV 格式校验器。
- 用户明确暂不支持单元格内实际换行，每条记录占一个物理行。以后有需要再讨论；UI 自动换行不属于这里的多行 CSV 支持。
- `LoadTexts()` 检查两列格式、整数编号和表内重复编号；错误行输出日志并跳过，其他正常行继续加入字典。
- 资源加载成功后先 `_texts.Clear()` 再填充，避免重复加载时将旧记录当作新表重复编号；资源加载失败时保留原有字典。当前是清空后逐行导入，未实现整表校验通过后统一替换。
- `GetText()` 使用 `TryGetValue`；编号不存在时输出错误并返回空字符串。`Interact()` 收到 null 或空字符串时直接结束，不再打印空日志。
- 启动时加载，交互时查询已有字典；没有新增每次交互重读文件或自动监听 Excel 的逻辑。
- 逐条打印编号与文字的测试日志已移除，保留加载数量和错误日志。面向玩家的文本集中管理，开发日志继续由代码输出。

当前交互提示资源与验证：

## 七、教学方式与沟通要求

- 使用中文，语气友好、清楚，可以称呼用户“宝宝”。
- 一次讲一个小知识点，安排一个可完成的小任务。
- 先解释“是什么、为什么做、完成后解决什么”，再给任务。
- 框架或数据功能先讲清数据从哪里来、交给谁处理、最后到哪里。
- 重点检查逻辑、结构、对象引用、初始化顺序和生命周期。
- 不把一般手打拼写、大小写或排版差异当成教学重点；影响编译、Unity 回调或引用的错误仍需清楚指出。
- 尊重用户自己选择的颜色和细节；`InPutManager` 的类名与文件名拼写明确保留。
- 用户没看懂时先停下来解释，不连续推进新概念。

每轮代码教学按以下方式：

1. 读取实际项目代码，确认当前进度。
2. 解释当前小任务的用途和执行流程。

## 九、注释与固定分区要求

完整规范见 [脚本分区与注释规范.md](脚本分区与注释规范.md)，模板见 [MonoBehaviourTemplate.cs.txt](Templates/MonoBehaviourTemplate.cs.txt)。

- 类和方法用简短中文 `<summary>` 说明功能。
- 参数用 `<param>` 说明作用；有返回值时写 `<returns>`；泛型类型参数使用 `<typeparam>`。
- 每个字段、局部变量和 foreach 迭代变量分别说明“保存什么、起什么作用”。
- 复杂方法按“第一步、第二步……”标注关键执行流程；简单单步方法不硬凑步骤。
- 注释简短、关键，随当前代码更新，不写长篇背景和未来计划。
- 使用普通注释分隔，不使用 `#region`。
- 固定分区内可按背包、设置等功能再分小组，事件回调也可和同功能方法放在一起；位置不决定调用时机或访问权限，CloseSettings 移入设置小组仍保持 private。

所有脚本固定保留以下八个分区，未使用的分区也保留：

```csharp
// ==================== 字段 ====================
// ==================== Unity 生命周期 ====================
// ==================== 初始化 ====================
// ==================== 对外接口 ====================
// ==================== 核心逻辑 ====================
// ==================== 事件响应 ====================
// ==================== 内部辅助 ====================
// ==================== 调试显示 ====================
```

保留分区不等于添加空方法。常量类、普通类和编辑器工具保留空标签即可，不因此改变继承关系。
